## 2. Key findings per venue

**Coinbase** is the closest analogue to Kalshi: a CDP key with only `View` and a self-describe endpoint (`key_permissions`) that Koine can call at connect time and again nightly. Gotchas: (a) a key is bound to one portfolio; (b) `trade_id` is not unique for adjusted fills, use `entry_id`; (c) fills cover Advanced Trade only; simple Buy/convert/staking flows show up only in the v2 `transactions` list (treat as transfers/adjustments); (d) the v2 transaction list is the only deposit/withdrawal source. OAuth is "limited to approved partners". The CDP ToS anti-aggregation/anti-sharing clause is the biggest open risk for a *public* track-record page (Koinly/CoinTracker are private-to-user, Koine is not).

**Binance** has the best read-only proof (`apiRestrictions`) and un-IP-restricted HMAC keys cannot be anything but read. The pain is ingestion: `myTrades` is per symbol AND capped at a 24-hour window, so symbol discovery plus `fromId` pagination is required; side ledgers (convert, dust, universal transfer, staking) each have 30/90-day windows. Binance global does not serve US traders; Binance.US is the same code path.

**Kraken** has the best *ledger* model for reconciliation: `Ledgers` returns every balance-affecting row with `refid`, `fee`, and a running `balance` per asset, so Koine can replay the whole account and check the last row against `Balance` exactly. Trades are all-time. Downsides: no self-describe endpoint (probe-based proof), low counters (backfill must be throttled).

**Bybit/OKX**: technically fine, but Bybit does not serve the US and OKX's API agreement forbids strategy-marketplace products without approval. **Gemini**: exclusive Auditor role is an excellent read-only guarantee; small user base. **Robinhood Crypto**: no fills or transfers endpoint, ledger would be lossy. **Hyperliquid**: address-keyed like Polymarket, fills carry `closedPnl`; only the last 10,000 fills are served and it is a perps venue (funding payments = a new row type).

## 3. Aggregators

- **Vezgo**: read-only, ~35 exchanges + chains, quote-only pricing. https://vezgo.com/pricing/
- **Mesh (formerly Front)**: pivoted to crypto payments; enterprise focus; pricing not public.
- **Zabo**: acquired by Coinbase 2021, shut down. **Covalent**: on-chain only.
- Verdict: an aggregator buys breadth, not verification. Koine's claim is "we pulled these numbers ourselves and checked the key was read-only"; an intermediary that holds the keys weakens that. Direct connectors for the first venues; revisit Vezgo for the long tail.

## 4. Ledger-modelling notes for multi-asset accounts

1. **Balance is a vector.** Replace the single `balance_micros` with `(asset, qty)` rows. BTC quantities need 8 decimals; 1e-6 rounding would corrupt reconciliation. Per-asset scale is the first invariant-1 decision to make explicitly.
2. **Fills are two-legged.** A spot fill debits one asset and credits another, plus a fee leg possibly in a third asset (Binance `commissionAsset` may be BNB; Kraken fee in quote; Hyperliquid `feeToken` USDC). Model a fill as ledger legs keyed by the venue fill id.
3. **Transfers** (deposits/withdrawals/internal/convert/dust/staking rewards) are external flows in asset units; equity-curve math needs them time-stamped so returns are flow-adjusted.
4. **USD equity curve** = sum of asset_qty(t) x price(t). Price sources: the venue's own public candles are free: Binance `/api/v3/klines` (1000 bars), Coinbase `product_candles` (350 bars), Kraken `OHLC` (last 720 bars; downloadable OHLCVT archive for history). Fallback: CoinGecko Demo (free, 10k/mo, 1 yr) or Basic $35/mo. Recommend daily close from the trader's own venue as the canonical mark.
5. **Reconciliation**: Kraken's running `balance` allows exact replay; Binance/Coinbase only give current balances, so reconcile "replayed vector == live vector" per asset with tolerance for dust and staking payouts. Koinly does exactly this per (wallet, asset); none of the tax tools *verify* read-only beyond call failure, so a self-describe check is a differentiator.
6. **History limits** to design around: Binance myTrades 24 h windows, Bybit 7-day, OKX 3-month fills, Hyperliquid 10k fills, Kraken counter budget.

## 5. Recommended venue order

1. **Coinbase Advanced Trade**: US, key-level `View`, Kalshi-style self-describe endpoint, stable `entry_id`, transfers via v2 with the same key. Do the CDP ToS legal read first.
2. **Kraken**: US, running-balance ledger makes reconciliation stronger than Coinbase; probe-based proof acceptable if documented.
3. **Hyperliquid**: cheapest build (Polymarket-shaped); US trader restriction and 10k-fill retention.
4. Later: Binance.US for breadth; Gemini as low-effort add. Skip Bybit/OKX/Crypto.com/Robinhood.
